# Cult UI foundation, first pass

This pass adopts the official Cult UI Halo Button, Halo Card and Halo Input sources from the [documented registry](https://www.cult-ui.com/docs/installation). It keeps React/Vite, Tailwind 4, the existing shadcn/Radix dialogs and tabs, Satoshi, and the supplied Remotely artwork. Base UI 1.9.0 and Motion 14.14.0 are pinned dependencies. Registry and original/local source hashes are in `cult-ui-sources.json`; MIT attribution ships in `public/licenses/cult-ui.txt` and therefore in both web and native bundles.

The source components are owned locally. `PrimaryAction` disables character staggering and optional layout animation so expanding form settings cannot move button hit areas over fields. The shared card/input adapters provide opaque surfaces and stable application APIs. Motion uses the component's reduced-motion handling; global CSS also disables nonessential CSS animation for that preference. Input focus indication and 44-pixel action targets remain explicit.

The first visual direction uses dark navy, cool blue accents, a quieter app header, email sign-in first on phones, restrained rim lighting, a decorative device illustration, and clearer device cards. Raw device keys sit in expandable details. The remote screen remains sticky and fullscreen controls retain their existing semantics. This is a first design pass for review, not a claim that every screen or manual accessibility criterion has been redesigned or certified.

Local preview artifacts are generated by browser tests: `artifacts/login-390.png`, `artifacts/login-1280.png`, `artifacts/cult-devices-390.png`, `artifacts/cult-mac-setup-1280.png` and the session screenshots. They use disposable accounts and synthetic desktop capture/mocked native input. No stock remote workspace is shipped in the app.

Do not blindly overwrite shared primitives with CLI updates. Review the upstream sources, local adaptations, accessibility and native/browser behavior, then update the hashes. Cult UI's source is installed manually from its registry JSON to preserve the existing application adapters; `components.json` also registers the namespace for future components.
